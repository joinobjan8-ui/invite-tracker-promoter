# PROMOTER Invite Tracking Bot (Render Free)

Telegram bot for the PROMOTER group: gives every user a personal invite link, counts unique new members who join through it, and shows `/topinviter` (up to 100). MongoDB Atlas keeps the data across Render restarts.

## How users use it
- **In the group:** tap **🔗 Get My Invite Link** (under the welcome message / `/topinviter`) or send `/mylink`. The bot posts the link *in the group* with a **📋 Copy My Link** button; tapping the link text itself also copies it. No private chat / START needed.
- The link message (and the user's command) is auto-deleted after `AUTO_DELETE_SECONDS` to keep the group clean.
- Several people joining within a couple of seconds get **one** combined welcome message.

## Limitations
- Only joins through a link generated by this bot are attributed; history cannot be reconstructed.
- Counts are unique Telegram accounts, not proof of real people - admins should review winners.
- The bot does not distribute prizes.

## Setup
1. **Bot:** create it with `@BotFather`, copy the token.
2. **MongoDB Atlas:** create a user + database, allow Render in Network Access, copy the connection string.
3. **Render:** New Web Service from your GitHub repo (render.yaml is included). Environment variables:
   - `BOT_TOKEN`, `MONGODB_URI` (required)
   - `GROUP_ID` = `@Promoter0007` or the numeric chat id (numeric is more reliable)
   - `DB_NAME` = `promoter_giveaway`
   - `WEBHOOK_SECRET` = any random string (Render can generate it)
4. **Admin:** make the bot an admin of the group with *Invite users via link* (needed for `chat_member` updates and link creation) and, optionally, *Delete messages* (for auto-delete).
5. **Webhook:** registered **automatically** on every start (needs `RENDER_EXTERNAL_URL`, which Render sets itself). You can still open `/setup-webhook?key=YOUR_WEBHOOK_SECRET` manually.

> After updating from an older version, just redeploy - the webhook is re-registered with the new `callback_query` update type automatically.

## Optional environment variables
| Variable | Default | Meaning |
|---|---|---|
| `LINK_COOLDOWN_SECONDS` | 3 | Min. seconds between /mylink or /topinviter per user (spam is silently ignored) |
| `TOP_N` | 5 | How many inviters the leaderboard shows (max 50) |
| `KEEPALIVE_SECONDS` | 300 | Self-ping interval to keep the free instance and MongoDB warm |
| `AUTO_SET_WEBHOOK` | 1 | Set `0` to disable automatic webhook registration |

## Keeping the free Render instance awake
Render Free sleeps after ~15 min without traffic, and the first message after that is slow. The bot pings itself every `KEEPALIVE_SECONDS`, but for best reliability also add a free monitor (UptimeRobot / cron-job.org) that opens `https://YOUR-SERVICE.onrender.com/health` every 5 minutes.

## Commands
- `/start` - help
- `/mylink` - your personal invite link (works in the group and in private chat)
- `/topinviter` - leaderboard

## Troubleshooting pages (use your WEBHOOK_SECRET as `key`)
- `/diag?key=SECRET` - bot admin status/permissions in the group, `GROUP_ID` match, webhook info and Telegram's last delivery error.
- `/test-send?key=SECRET` - posts one test message to the group and shows Telegram's raw answer. If this works, sending is fine.

In the Render logs each step is printed: `command ...`, `-> sendMessage ...` (started) and `sendMessage ... ok=True` (finished). A `->` line without a matching finished line means the request hung.

## Owner-only control commands
Set the Render environment variable `OWNER_ID` to the Telegram numeric user ID of the bot owner (not a username). Only that user receives responses to the owner control commands:

- `/help` or `/owner` — show controls and current settings
- `/welcome_on` / `/welcome_off` — toggle welcome messages for new members
- `/automsg_on` / `/automsg_off` — toggle the recurring group reminder (every 2 minutes)
- `/allmsg_on` / `/allmsg_off` — allow normal member messages, or delete all non-admin group messages
- `/linkmedia_on` / `/linkmedia_off` — toggle deletion of links, photos/media, and inline-button messages from non-admins

The bot must be a group admin with **Delete messages** permission for moderation to work. Keep `allmsg_on` if members should be able to chat normally. `linkmedia_on` can still block links/media/buttons while ordinary text chat remains allowed. Settings are saved in MongoDB. If `OWNER_ID` is missing, owner controls are disabled.


## Performance & fixes (fast edition)
- `/mylink`, `/topinviter` and the buttons reply in well under a second (after warm-up).
- Old bug: every Telegram call went through a 3.2 s *global* lock and every group message triggered an admin lookup, so replies queued for minutes. Now only `sendMessage` is paced (0.35 s, outside any lock), admin lookups happen only for restricted messages and are cached 60 s, and settings/links/leaderboard are cached.
- Leaderboard uses 2 Mongo queries (no per-row Telegram call).
- Anonymous admins work for admin commands; `/mylink` from an anonymous admin asks them to turn off *Remain Anonymous* or use the buttons.
- An admin-check failure never deletes an admin's message.
- With `/allmsg_off`, `/mylink` and `/topinviter` still work.
- The referral is counted *before* the welcome message is sent.
- Webhook auto-registers on start, bot self-pings to stay awake, duplicate webhook retries are ignored.
- Fixed the reminder showing a literal `\n`.
- `tests_offline.py` runs the whole flow against a fake Telegram/Mongo (no network needed).
